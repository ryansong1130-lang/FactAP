# 환각 검사 기준 설명서

각 기준 파일(기준 폴더) 맨 위의 설명을 모은 문서예요. `기준_설명서_만들기.py` 로 자동으로 만들었어요.

## 0단계와 1단계

### `단계0_답변거부.py`

```text
단계 0. 답변 거부 거르기


■ 무엇을 하나요?
  사용자가 가져온 AI 답변이 '답변 거부'인지 먼저 확인해요.
  답변 거부면 환각 위험도를 계산하지 않고 "답변 거부(환각 아님)"라고 보여 줘요.

■ 왜 필요한가요?
  우리 조는 "AI가 답변을 거부한 경우에는 환각으로 정의하지 않는다"고 정했어요.
  거부한 답변에는 틀린 주장이 없으니, 다른 기준으로 검사하면 엉뚱한 점수가 나와요.

■ 어떻게 판단하나요?  (예선의 글로 된 답변 거부 18건과 정상 답변 1,170건을 비교해서 정함)
  거부 답변은 공통적으로 "나는 답할 수 없다" + "이유, 사과, 대안 중 하나"로 이루어져 있었어요.

  ① 능력 한계 표현 (꼭 있어야 함)
     AI '자기 자신'이 답할 수 없다고 말하는 표현이에요.
     예) "확인해 드릴 수 없습니다", "제시하기 어렵습니다", "확신할 수 없습니다", "제시하지 않겠습니다"
     ※ "알 수 없다"는 넣지 않았어요. 논리 문제에서는 "알 수 없다"가 정답일 수 있어서,
       넣으면 정상 답변 33건이 거부로 잘못 걸렸어요.

  ② 보조 신호 (하나 이상 있어야 함)
     - 거절 이유: "지어낼", "정확하지 않은", "잘못된 인용", "환각"
     - 대안 안내: "직접 확인하시려면", "KCI에서", "알려 주시면"
     - 사과: "죄송"
     ※ ①만 보면 정상 답변 중간의 문장까지 걸려서(19건), ②를 함께 요구했어요.

  ③ 예외: "그런 논문은 존재하지 않습니다", "글에 언급되지 않았습니다"처럼
     '질문의 대상이 없다'고 주장하는 답변은 거부가 아니에요.
     가짜 전제를 지적한 정답일 수도 있고, 실제로 있는 것을 없다고 한 환각일 수도 있어서
     환각 검사를 계속해야 해요. (예선의 가짜 전제 문항 정답 5건이 이 예외로 지켜졌어요)

  ④ 빈 답변이나 기호만 있는 답변은 "입력 확인 필요"로 따로 알려 줘요.

  ⑤ 짧은 거부 (2026-11-14 추가): "답변 불가", "모르겠습니다", "확인할 수 없습니다"처럼
     100자 이하의 짧은 답변이 '답을 못 한다'는 말뿐이면, 보조 신호가 없어도 답변 거부로 봐요.
     예선의 거부 답변은 모두 길어서 이 경우가 없었는데, 앱에 "답변 불가"를 넣으면 거부로 못 알아보고
     검사 AI가 '질문에 답하지 않음'이라고 보아 입력 상충으로 잘못 나왔어요.
     "잘 모르겠지만 아마 1592년일 거예요"처럼 거부 뒤에 답을 덧붙인 경우는 답을 한 것이라 거부가 아니에요.
     ※ "알 수 없다"는 여기서도 넣지 않았어요 (논리 문제의 정답일 수 있어서).
     "글에는 그 정보가 없으므로 답할 수 없습니다"처럼 글이나 조건을 근거로 든 답변도 거부가 아니에요.
     지문 문제에서는 이것이 정답일 수 있어요. (처음 규칙은 예선의 이런 지문 정답 2건을 거부로 잘못 봐서
     이 예외를 더했어요. 지금은 예선 정상 답변 1,170건 중 거부로 잘못 본 답변이 0건이에요.)

■ 글자 수 기준은 왜 안 쓰나요?
  예선의 실제 답변 거부 18건은 165~1,501자(중간값 약 520자)로 길었어요.
  요즘 AI는 거부할 때도 이유와 확인 방법을 길게 설명하기 때문이에요.

■ 예선 검증 결과
  글로 된 답변 거부 18건 중 16건을 찾았고, 정상 답변 1,170건 중 거부로 잘못 본 답변은 0건이에요.
  놓친 2건은 "아직 공식적으로 확인되지 않았습니다"처럼 애매하게 쓴 답변이에요.
  (이 규칙은 같은 자료로 만들었으므로 새 답변으로 다시 확인해야 해요)

■ 결과
  판정: "답변 거부" / "거부 아님" / "입력 확인 필요"
  검사(자료)의 결과에서 세부["판정"]으로 확인해요. 위험도는 항상 None 이에요(점수에 넣지 않음).

■ 직접 시험하기
  python 기준/단계0_답변거부.py
```

### `단계1_유형분류.py`

```text
단계 1. 답변 유형 분류


■ 무엇을 하나요?
  질문과 답변을 보고 6개 유형(사실 지식형, 수치 계산형, 논리 추론형, 출처 인용형, 지문 이해형, 코드 결과형)
  중 하나로 분류해요. 유형에 따라 다시 물어볼 상위 3개 모델과 유형별 기준 ⑤⑥이 정해져요.

■ 어떻게 분류하나요?  (참고 논문: 김학수·안영훈·서정연, 2003, 「한국어 질의응답시스템을 위한
  지지벡터기계 기반의 질의유형분류기」, 정보과학회논문지 30(5))
  논문의 4단계를 그대로 따랐어요.
  1) 자질 추출: 질문과 답변을 단어로 자르고, "얼마, 몇"은 %의문_수량, "논문, 저자"는 %출처어처럼
     의미 표지로 바꿔요.
  2) 자질 선택: 카이제곱 통계로 유형을 잘 구분하는 단어 3,000개만 남겨요.
  3) 가중치: tfc 가중치(논문에서 가장 좋았던 방법)로 숫자 벡터를 만들어요.
  4) 분류: 선형 SVM으로 6개 유형 점수를 계산하고 가장 높은 유형을 골라요.

■ 예선 검증 결과 (같은 질문이 학습과 시험에 동시에 들어가지 않게 나눈 교차검증)
  정확도 94.2%. 수치·출처·지문·코드형은 99.5~100%, 사실형 81.5%, 논리형 84.5%.
  확신도(1등과 2등 점수 차이)가 0.5보다 작으면 '애매함'으로 표시해요 (전체의 약 9.5%).
  애매함이 아닌 답변의 정확도는 96.9%예요.

■ 애매할 때는?  (2026-11-15 바꿈)
  1순위와 2순위 유형의 ⑤⑥을 모두 실행하고, 두 결과를 '그 유형일 확률'로 섞어요. (설정.애매하면_두_유형_섞기)
  1순위 확률 = 1 ÷ (1 + e^(−6 × 확신도)). 기울기 6은 예선 교차 검증에서 애매했던 답변 102개에 맞춘 값이에요.
  앱 화면에도 1순위와 2순위 유형, 각각의 확률을 보여 주고, 사용자가 유형을 직접 고를 수도 있어요.
  (직접 고르면 섞지 않고 그 유형으로만 검사해요)

■ 결과 (유형_정하기 함수)
  {"유형", "2순위", "확신도", "애매함", "1순위_확률", "유형_불일치", "질문만_유형"}
  유형_불일치: 질문만 보고 정한 유형과 질문+답변으로 정한 유형이 다름 → 참고로만 보여 줘요 (점수에는 안 넣음)

■ 필요한 파일
  도구/유형_분류기.py, 도구/유형_분류_모델.json
  (질문을 더 모아 다시 학습하려면: 도구 폴더에서 python 유형_분류기.py 학습)

■ 한계
  우리 조가 만든 120개 질문으로 학습했기 때문에 처음 보는 질문에서는 정확도가 더 낮을 수 있어요.

■ 직접 시험하기
  python 기준/단계1_유형분류.py
```

## 공통 기준 ①~④ (모든 유형)

### `공통1_질문답변일치.py`

```text
공통 기준 ① 질문-답변 일치도  (맡는 환각: 입력 상충)


■ 무엇을 확인하나요?
  답변이 질문이 묻는 것에 제대로 답했는지, 그리고 질문(지문)의 조건을 바꾸거나
  질문에 없는 조건을 덧붙이지 않았는지 확인해요.

■ 왜 필요한가요?
  입력 상충은 "답변이 사용자의 질문이나 지문의 내용·조건과 다르거나, 없는 내용을 덧붙인 것"이에요.
  예선에서 입력 상충은 14건(지문형 12, 논리형 2) 나왔어요.
  예) 성별 정보가 없는데 "손자"로 단정함 (LOGIC-20)

■ 어떻게 확인하나요?
  1) 검사 AI 3개(그 유형의 상위 3개 모델)가 "질문에 맞게 답했는가, 조건을 바꾸거나 덧붙였는가"를
     "문제 있음 / 문제 없음"과 근거 한 문장으로 판정해요. (지시문은 도구/AI_호출.py)
  2) "문제 있음"이라고 한 검사 AI의 수를 세요.
  ※ 유형 분류의 '유형 불일치'(질문만 본 유형 ≠ 답변까지 본 유형)는 참고로만 적어 두고 점수에는 넣지 않아요.

■ 점수 (0 = 안전, 1 = 위험)
  위험도 = 문제 있음이라고 한 검사 AI 수 ÷ 판정한 검사 AI 수
  검사 AI 결과가 없으면 "확인 불가"

■ 예선 검증으로 알게 된 점
  '유형 불일치' 하나만으로는 입력 상충 14건 중 0건을 잡았어요. 입력 상충은 대부분 유형은 맞게
  답하면서 내용을 덧붙인 경우였기 때문이에요. 그래서 판단은 검사 AI가 해요.

■ 유형 불일치 +0.2를 뺀 이유 (2026-11-15)
  처음에는 유형 불일치가 있으면 +0.2를 더했어요. 그런데 앱에서 "로지스틱 회귀가 뭐야?"처럼 처음 보는 질문을 넣으면
  검사 AI 3개가 모두 '문제 없음'이라고 해도 이 +0.2 때문에 맞는 답이 '보통'으로 나왔어요.
  처음 보는 질문처럼 시험하려고 예선 120문항을 5묶음으로 나눠 교차 검증해 보니,
    - 정답 1,102개 중 유형 불일치 67개 (6.1%)
    - 환각 68개 중 유형 불일치 2개 (2.9%)
    - 입력 상충 14건 중 유형 불일치 0건
  으로, 유형 불일치는 환각보다 정답에서 더 자주 생겼어요. 환각 신호가 아니라 '분류기가 헷갈렸다'는 신호라서 뺐어요.
  대신 유형이 애매하면 두 유형으로 모두 검사해서 확률로 섞어요 (검사_실행.py, 설정.애매하면_두_유형_섞기).

■ 한계
  검사 AI도 틀릴 수 있어요. 3개의 다수결과 근거 문장을 함께 보여 줘서 사용자가 판단할 수 있게 해요.

■ 필요한 것
  자료["검사AI"] (검사AI_실행 결과), 자료["이전결과"]["유형 분류"] (있으면)
```

### `공통2_출처답변연관성.py`

```text
공통 기준 ② 출처-답변 연관성  (맡는 환각: 사실 상충)


■ 무엇을 확인하나요?
  사용자가 입력한 출처(그 AI가 참고했다고 한 자료)의 내용이 답변을 실제로 뒷받침하는지 확인해요.

■ 왜 필요한가요?
  AI는 출처를 붙여 놓고도 출처에 없는 내용을 말하거나, 출처와 반대되는 내용을 말할 수 있어요.
  출처가 있다고 해서 답변이 맞다는 보장은 없기 때문에 출처와 답변을 직접 맞춰 봐야 해요.

■ 어떻게 확인하나요?
  1) 출처 준비: 출처 칸에서 링크(http…)를 찾아 웹 페이지 본문을 가져와요. 링크가 아닌 글을 붙여 넣었다면
     그 글을 그대로 써요.
  2) 문장 맞추기: 답변을 문장으로 나누고, 문장마다 출처 본문에서 가장 비슷한 부분(3문장 묶음)을 찾아요.
     비교는 '글자쌍'(글자 2개씩 묶음)이 얼마나 겹치는지로 해요. 조사·어미가 달라도 비교할 수 있어요.
  3) 1차 판정(프로그램):
     - 겹치는 비율이 기준값(설정.출처지지_기준, 0.35) 이상 → "비슷한 내용 있음"
     - 그보다 낮음 → "출처에 없음"
     - 비슷한 부분은 있는데 숫자가 다름 → "숫자 다름"(반대일 가능성)
  4) 2차 판정(검사 AI, API 키가 있을 때): "출처에 없음"과 "숫자 다름" 문장만 골라,
     그 문장과 출처의 비슷한 부분을 검사 AI에 주고 "뒷받침 / 반대 / 언급 없음"으로 판정하게 해요.

■ 점수 (0 = 안전, 1 = 위험)
  검사 AI 판정이 있으면: 위험도 = (반대 문장 수 + 0.5 × 언급 없음 문장 수) ÷ 확인한 문장 수
  프로그램 판정만 있으면: 위험도 = (숫자 다름 문장 수 + 0.5 × 출처에 없음 문장 수) ÷ 확인한 문장 수
  출처를 입력하지 않음 → "해당 없음"
  링크를 열지 못함(로그인 필요, PDF 등) → "확인 불가" + 본문을 직접 붙여 넣어 달라고 안내

■ 예선 검증
  예선은 웹 검색 없이 진행해서 출처가 있는 답변이 거의 없었어요. 그래서 이 기준은 예선 자료로 검증하지
  못했어요. 새 질문으로 앱을 시험할 때 꼭 확인해야 해요.

■ 한계
  - 출처가 영어이고 답변이 한국어면 글자쌍 비교가 안 돼요. 이때는 검사 AI 판정에 의존해요.
  - 출처 페이지가 바뀌었거나 사라졌으면 확인할 수 없어요.

■ 필요한 것
  자료["출처"], 자료["검사모델"](검사 AI 모델 ID 목록, 있으면), 인터넷 연결
```

### `공통3_상위모델일치.py`

```text
공통 기준 ③ 상위 모델 답변 일치도  (맡는 환각: 사실 상충)


■ 무엇을 확인하나요?
  같은 질문을 그 유형의 상위 3개 모델(예선에서 가장 정확했던 모델)에 다시 물어서,

■ 왜 필요한가요?
  예선에서 사실 상충은 47건으로 가장 많은 환각이었어요. 정답을 모르는 질문에서도,
  믿을 만한 모델 여러 개와 답이 다르면 틀렸을 가능성이 높아요.

■ 어떻게 확인하나요?
  1) 전체 실행 파일이 상위 3개 모델에 같은 질문을 예선과 같은 설정(기본 설정, 지시문 없음)으로 보내요.
  2) 각 답변에서 '최종 답'을 뽑아요. (도구/글_도구.py 의 최종답_뽑기)
     - 앞부분의 굵은 글씨, "정답은 …", "따라서 …" 뒤의 말, 코드형은 코드 블록 안의 출력
  3) 프로그램이 비교할 수 있으면 직접 비교해요.
     - 숫자가 있으면 숫자로 비교 (쉼표, 단위 무시)
     - 오류 이름(IndexError 등)이 있으면 오류 이름으로 비교
     - 30글자 이하의 짧은 답이면 글자로 비교
  4) 긴 서술형이라 프로그램이 비교하기 어려우면, 검사 AI의 '참고답변_일치'(예/아니오) 다수결을 써요.

■ 점수 (0 = 안전, 1 = 위험)
  위험도 = 1 − (사용자 답과 같은 상위 모델 수 ÷ 비교한 상위 모델 수)

  상위 모델끼리도 답이 모두 다르면 "판단 어려움"을 근거에 적어요 (문제가 어렵거나 답이 여러 개일 수 있음).

■ 예선 검증 결과
  검증/예선_검증.py 로 확인한 결과를 README 에 적어 두었어요.

■ 한계
  상위 모델 3개가 같은 오답을 내면 못 잡아요(모델들은 학습 자료가 겹쳐서 같은 실수를 하기도 해요).
  그래서 계산 재검산, 코드 실행, 출처 검색처럼 프로그램으로 직접 확인하는 기준과 함께 써야 해요.

■ 필요한 것
  자료["상위모델_답변들"], 자료["검사AI"](서술형일 때)

### `공통4_내부일관성.py`

```text
공통 기준 ④ 답변 내부 일관성  (맡는 환각: 맥락 상충)


■ 무엇을 확인하나요?
  답변 안에서 결론, 숫자, 이름이 앞뒤로 바뀌거나 서로 모순되는 곳이 있는지 확인해요.

■ 왜 필요한가요?
  맥락 상충은 "답변 안에서 앞뒤 내용이 서로 모순되는 것"이에요. 정답을 몰라도 답변만 보고 찾을 수 있어요.
  예선에서 맥락 상충은 7건 나왔어요.
  예) 노벨상 수상자 수를 "총 4명" → "세 명" → "단 한 명"으로 번복 (FACT-06)
      첫 줄 결론은 "나", 마지막 결론은 "다" (LOGIC-17)
      최종 답 "2, TypeError"가 앞의 설명 "(14, 0)"과 모순 (CODE-16)

■ 어떻게 확인하나요? (프로그램 규칙 3개 + 검사 AI)
  1) 결론 비교: 첫 줄의 굵은 글씨 답과, 뒷부분에서 "따라서/그러므로/최종/정답은"이 있는 마지막 줄의
     굵은 글씨 답을 비교해요. 둘 다 선택지(가, 나, A, ①…)이거나 둘 다 짧은 숫자 답일 때만 비교해요.
     → 선택지가 다르거나 숫자가 하나도 겹치지 않으면 '결론이 바뀜'
  2) 고쳐 말하기 표현: "정정합니다", "앞서 생각했던 답이 …였으나", "혼동을 드려", "다시 말씀드리면",
     "(X)"(단, (O)와 함께 쓴 O/X 설명은 제외)처럼 답변 스스로 앞의 말을 뒤집는 표현을 찾아요.
     예선 채점에서 이렇게 스스로 번복한 답변은 맥락 상충으로 판정했기 때문이에요.
  3) 같은 대상의 숫자 비교: "과학자는 총 4명입니다" … "과학자는 단 한 명입니다"처럼
     같은 주어(○○은/는)에 같은 단위로 다른 숫자를 '단정'(…입니다)하면 모순 후보로 봐요.
     한글 숫자(한~열)도 숫자로 바꿔서 비교해요. "가정하면", "경우", "라면"이 있는 문장은 빼요(추론 과정이라서).
  4) 검사 AI: 검사 AI 지시문의 '앞뒤_모순' 항목("있음/없음"과 해당 문장)을 다수결로 봐요.

■ 점수 (0 = 안전, 1 = 위험)
  프로그램 점수: 결론이 바뀜 0.8, 고쳐 말하기 0.6, 숫자 모순 0.4 중 가장 큰 값
               (신호가 2개 이상이면 +0.2)
  검사 AI가 있으면 → 프로그램 점수와 "있음" 비율 중 큰 값
  프로그램도 못 찾고 검사 AI도 없으면 → 0 (근거에 '검사 AI 없이 확인함'이라고 적음)

■ 예선 검증 결과 (검증/예선_검증.py, 검사 AI 없이 프로그램 규칙만)
  - 처음 만든 숫자 규칙은 계산·논리 풀이의 중간 숫자를 모순으로 잘못 잡아 정답 27개를 오탐했어요.
    그래서 '같은 주어 + 단정하는 말 + 가정 문장 제외'로 좁혔어요.
  - 고친 뒤: 맥락 상충 7건 중 3건(FACT-06, LOGIC-17, CITE-10)을 잡고, 정답 1,102개 중 오탐은 0개예요.
  - 나머지 4건(추론 과정 속 모순, 오타로 생긴 모순 등)은 문장 뜻을 이해해야 해서 검사 AI가 맡아요.

■ 한계
  "처음엔 A라고 생각했지만 다시 계산하면 B"처럼 스스로 고친 답변은 최종 답이 맞더라도 위험도가 올라가요.
  예선 채점 기준(번복 = 맥락 상충)과 같게 한 것이지만, 화면에는 '고쳐 말한 문장'을 함께 보여 줘서
  사용자가 최종 답을 판단할 수 있게 해요.

■ 필요한 것
  자료["답변"], 자료["검사AI"](있으면)

### `사실5_핵심정보대조.py`

```text
사실 지식형 기준 ⑤ 핵심 정보 대조  (맡는 환각: 사실 상충)


■ 무엇을 확인하나요?
  답변의 핵심 정보(누가, 언제, 어디서, 무엇)가 한국어 위키백과의 내용과 같은지 확인해요.

■ 왜 필요한가요?
  사실 지식형 질문은 정답이 정해져 있어서, 믿을 만한 자료와 직접 맞춰 보면 틀린 답을 찾을 수 있어요.
  ③(상위 모델 답변 일치도)은 'AI끼리 같은지'를 보지만, 이 기준은 'AI가 아닌 자료'와 맞춰 봐요.
  그래서 상위 모델들이 함께 틀리는 경우를 보완해요.

■ 어떻게 확인하나요?
  1) 핵심 정보와 검색어 정하기
     - 검사 AI가 있으면: 검사 AI가 뽑은 핵심정보 [{항목, 값}]과 검색어를 써요.
     - 없으면(프로그램 규칙): 답변 앞부분의 굵은 글씨(20자 이하)와 연도를 핵심 정보로,

  2) 위키백과 찾기: 검색어로 한국어 위키백과를 검색해 가장 관련 있는 문서 본문을 가져와요.
     못 찾으면 첫 번째 핵심 정보(예: '숭례문')로 한 번 더 검색해요. (도구/웹_도구.py, 무료)
  3) 대조: 핵심 정보마다 위키백과 본문에 있는지 봐요.
     - 숫자(연도, 날짜)는 그 숫자가 본문에 있는지
     - 글(이름, 장소)은 띄어쓰기를 무시하고 본문에 그대로 있는지, 또는 글자쌍이 80% 이상 겹치는지
       (괄호 속 한자·영어는 빼고 비교)

■ 점수 (0 = 안전, 1 = 위험)
  위험도 = 0.8 × (위키백과에서 찾지 못한 핵심 정보 수 ÷ 확인한 핵심 정보 수)
  위키백과에 없다고 해서 반드시 틀린 것은 아니라서 최대 0.8로 정했어요.
  핵심 정보가 없음 → "해당 없음", 위키백과를 열지 못함 → "확인 불가"

■ 예선 검증
  인터넷 검색이 필요해서 만든 사람의 환경(인터넷 차단)에서는 실제로 돌려 보지 못했어요.
  앱 담당 조원이 예선 사실형 답변으로 꼭 확인해 주세요.

■ 한계
  - 위키백과 문서가 다른 주제로 잘못 골라지면 맞는 정보도 '없음'이 될 수 있어요. 그래서 근거에
    어떤 위키백과 문서와 비교했는지 문서 제목을 보여 줘요.
  - "그런 사람은 없습니다"처럼 질문의 전제가 틀렸다고 답한 경우는 비교할 핵심 정보가 없어 "해당 없음"이 돼요.

■ 필요한 것
  자료["질문"], 자료["답변"], 자료["검사AI"](있으면), 인터넷 연결

### `사실6_부가설명검증.py`

```text
사실 지식형 기준 ⑥ 부가 설명 검증  (맡는 환각: 사실 상충)


■ 무엇을 확인하나요?
  질문이 묻지 않았는데 답변이 덧붙인 세부 사실(날짜, 장소, 배경 설명 등)이 맞는지 확인해요.

■ 왜 필요한가요?
  예선 사실형 환각 17건 중 대부분이 '부분 환각'이었어요. 핵심 답은 맞았지만 덧붙인 설명이 틀린 경우예요.
  예) 숭례문이 "현재도 국보 제1호 지위를 유지"한다고 함 (FACT-17, 실제로는 지정 번호가 폐지됨)

■ 어떻게 확인하나요?
  1) 덧붙인 문장 고르기
     - 검사 AI가 있으면: 검사 AI가 뽑은 '덧붙인_사실'과 각각의 판정(맞음/틀림/확인 불가)을 써요.
       검사 AI 3개가 뽑은 문장 중 비슷한 것끼리 묶어 다수결로 판정해요.

       '구체적인 사실' 문장을 골라요(최대 8개).
  2) 위키백과와 맞춰 보기: ⑤에서 가져온 위키백과 본문(없으면 새로 검색)에서 문장마다 가장 비슷한 부분을 찾아요.
     - 비슷한 부분이 있고 숫자도 같음 → 맞음
     - 비슷한 부분이 있는데 숫자가 다름 → 틀림 의심
     - 비슷한 부분이 없음 → 확인 안 됨
  3) 문장마다 점수를 매겨요.

■ 점수 (0 = 안전, 1 = 위험)
  문장 점수: 검사 AI 다수가 '틀림' → 1, 위키백과와 숫자가 다름 → 0.7, 확인 안 됨 → 0.3, 맞음 → 0
  위험도 = 문장 점수의 평균
  덧붙인 문장이 없음 → "해당 없음", 검사 AI도 없고 위키백과도 못 열면 → "확인 불가"

■ 예선 검증
  ③ 방식처럼 상위 모델 답변과 연도를 비교하는 규칙도 시험해 봤지만, 사실형에서 환각 3건을 잡는 동안
  정답 8건을 잘못 잡아서 쓰지 않기로 했어요. 그래서 이 기준은 위키백과와 검사 AI로만 판단해요.
  인터넷이 필요해서 만든 사람의 환경에서는 실제로 돌려 보지 못했어요. 앱 담당 조원이 꼭 확인해 주세요.

■ 한계
  - 위키백과에 없는 내용은 '확인 안 됨'이 되어 위험도가 조금(0.3) 올라가요.
  - "현재도 ~이다"처럼 시점이 바뀐 사실은 위키백과 문서가 오래됐으면 확인하기 어려워요.

■ 필요한 것
  자료["질문"], 자료["답변"], 자료["검사AI"](있으면), 자료["이전결과"]["핵심 정보 대조"](있으면), 인터넷 연결

## 수치 계산형 ⑤⑥

### `수치5_계산재검산.py`

```text
수치 계산형 기준 ⑤ 계산 재검산  (맡는 환각: 사실 상충)


■ 무엇을 확인하나요?
  답변의 풀이에 나온 계산식(예: 450 − 360 = 93)을 프로그램이 직접 다시 계산해서 틀린 곳이 있는지 확인해요.
  질문 자체가 계산식(예: 4,837 × 2,916은?)이면 직접 계산해서 답변의 최종 답과도 비교해요.

■ 왜 필요한가요?
  AI는 식은 맞게 세워 놓고 계산 결과를 틀리게 쓰는 경우가 있어요. 사람이 하나하나 계산해 보지 않으면
  놓치기 쉽지만, 프로그램은 정확하게 다시 계산할 수 있어요.
  예) "450 − 360 = 93점" (CALC-11, 실제 90), "4,837 × 2,916 = 14,104,792" (CALC-20, 실제 14,104,692)

■ 어떻게 확인하나요?
  1) 식 정리: 수식 표시($…$, \times, \frac{a}{b})를 지우고, ×·÷·² 같은 기호와 1,000 같은 쉼표를
     계산할 수 있는 모양으로 바꿔요. 5% 는 5/100 으로 바꿔요.
  2) 식 찾기: "식 = 값" 또는 "식 = 식 = 값"처럼 등호(=, ≈)로 이어진 부분을 찾아요.
     x, y 같은 문자가 들어간 식(방정식)은 계산할 수 없으므로 건너뛰어요.
  3) 다시 계산: 등호 양쪽을 계산해서 비교해요. 계산은 숫자와 + − × ÷ 거듭제곱, 괄호만 허용하는
     안전한 방법으로 해요(아무 코드나 실행하지 않음).
     - '=' 이면: 오른쪽 값이 쓴 자릿수만큼 반올림·버림한 차이(예: 3.14 면 0.01)까지는 같다고 봐요.
     - '≈', '약' 이면: 10%(설정.어림_허용오차)까지 같다고 봐요. ("2¹⁰ ≈ 10³" 같은 어림 설명을 틀렸다고 보지 않으려고)
  4) 질문이 바로 계산식이면(예: "4,837 × 2,916은 얼마인가요?", "2의 30제곱은?") 직접 계산해서
     답변의 첫 번째 굵은 글씨 답(또는 최종 답)과 비교해요.

■ 점수 (0 = 안전, 1 = 위험)
  틀린 계산이 하나라도 있음 → 1 (예선 채점에서도 계산 실수는 환각으로 판정)
  확인한 식이 모두 맞음 → 0
  계산할 수 있는 식이 하나도 없음 → "해당 없음"
  ※ 프로그램이 직접 계산한 결과라서, 위험도 1이면 종합 위험도를 최소 0.8로 올려요(설정.py).

■ 예선 검증 결과
  README의 검증 표를 보세요.

■ 한계
  - 식을 세우는 방법 자체가 틀린 경우(예: 더해야 할 것을 곱함)는 계산이 맞으면 못 잡아요.
    이런 경우는 ③ 상위 모델 답변 일치도가 맡아요.
  - 말로만 쓴 계산("360에서 90을 빼면 270")은 찾지 못해요.

  자료["질문"], 자료["답변"]

출처 인용형 기준 ⑤ 출처 실재 확인  (맡는 환각: 사실 상충)

  자료마다: 있음 0, 비슷한 것만 있음 0.5, 찾지 못함 1(한국어 제목이면 0.6), DOI 없음 1
  위험도 = 자료 점수의 평균 (인터넷 오류로 확인 못 한 자료는 빼고 계산)

■ 한계

    "찾지 못함"이 나올 수 있어서 점수를 0.6으로 낮췄어요. 화면에 KCI·RISS·DBpia 에서 직접 찾아보라고 안내해요.
  - 책(단행본)은 논문 데이터베이스에 없는 경우가 많아요.

■ 필요한 것
  자료["답변"], 자료["검사AI"](있으면), 인터넷 연결
```

■ 점수 (0 = 안전, 1 = 위험)
  위험도 = 틀린 항목 수 ÷ 비교한 항목 수
  ⑤에서 '있음'인 자료가 없음 → "해당 없음" (없는 논문은 ⑤에서 이미 위험으로 판정)

■ 한계
  - 데이터베이스 자체에 권·호가 비어 있는 논문이 있어요. 그 항목은 비교하지 않아요.
  - 옛날 논문(예: 1950년 Mind)은 권 번호를 로마 숫자(LIX)로 적기도 해서, 로마 숫자는 바꿔서 비교해요.

## 코드 결과형 ⑤⑥

### `코드5_코드실행.py`

```text
코드 결과형 기준 ⑤ 코드 직접 실행  (맡는 환각: 사실 상충)


■ 무엇을 확인하나요?
  질문 속 파이썬 코드를 우리 프로그램이 직접 실행해서, 답변이 말한 출력값(또는 오류 이름)이
  실제 결과와 같은지 확인해요.

■ 왜 필요한가요?
  코드의 출력은 실행해 보면 정답이 하나로 정해져요. 다른 AI에게 묻는 것보다 훨씬 확실한 방법이에요.
  예) 딕셔너리 길이가 3인데 4라고 답함 (CODE-11), 실제로는 (14, 0)인데 "2, TypeError"라고 답함 (CODE-16)

■ 어떻게 확인하나요?
  1) 코드 뽑기: 질문에서 ```로 감싼 부분, 없으면 첫 빈 줄 뒤의 코드를 뽑아요. (도구/글_도구.py 의 코드_뽑기)
  2) 안전하게 실행: 따로 띄운 파이썬에서 3초 제한으로 실행해요. 파일·인터넷·시스템을 건드리는 코드는
     실행하지 않아요. (도구/코드_도구.py)
  3) 비교
     - 실제로 오류가 나면: 답변 앞부분에 같은 오류 이름(예: ZeroDivisionError)이 있는지 봐요.
     - 실제로 출력이 나오면: 답변이 내세운 출력값(코드 블록, `…`, **…**, 첫 줄)과 실제 출력을 비교해요.
       이 기준은 '값'이 맞는지만 봐요. 따옴표, 괄호, 쉼표, 띄어쓰기 같은 '형식' 차이는 무시하고,
       형식은 ⑥ 오류 여부·출력 형식 일치에서 따로 봐요.
       출력이 여러 줄이면 줄마다 확인해요.

■ 점수 (0 = 안전, 1 = 위험)
  오류: 같은 오류 이름 → 0, 오류라고만 하고 이름을 안 씀 → 0.5, 다른 오류이거나 오류가 아니라고 함 → 1
  출력: 값이 같음 → 0, 다름 → 1, 여러 줄이면 → 1 − (맞은 줄 수 ÷ 전체 줄 수)
  질문에 코드가 없음 → "해당 없음" / 안전 때문에 실행하지 않음, 시간 초과 → "확인 불가"
  ※ 이 기준은 프로그램이 직접 확인한 결과라서, 위험도 1이 나오면 종합 위험도를 최소 0.8로 올려요(설정.py).

■ 예선 검증 결과
  README의 검증 표를 보세요. (코드형 200개 답변을 실제로 돌려 확인함)

■ 한계
  - 답변이 출력값을 어디에 썼는지 프로그램이 못 찾으면 '다름'으로 잘못 볼 수 있어요.
    그래서 근거에 '실제 출력'과 '답변이 말한 출력'을 함께 보여 줘요.
  - random, time 처럼 실행할 때마다 결과가 다른 코드나, 파일·입력이 필요한 코드는 확인하지 못해요.

■ 필요한 것
  자료["질문"](코드 포함), 자료["답변"]
```

         (예: ⑥ 서지 정보 일치는 ⑤ 출처 실재 확인에서 찾은 논문을 그대로 씀)
  5단계  점수 합치기 → 종합 위험도와 등급
         유형이 애매했으면: (1순위 확률 × 1순위 유형 위험도) + (2순위 확률 × 2순위 유형 위험도)

■ 점수 합치기와 등급 (설정.py 4번. 예선 자료 1,170개로 확인했어요)
  1) 위험도가 나온 기준만 모아요. ('해당 없음', '확인 불가'는 빼요)
  2) 종합 위험도 = 가중 평균 (설정.합치는_방법 = "가중 평균")
       (기준마다 위험도 × 중요도)의 합 ÷ (계산한 기준들의 중요도 합)
     중요도(설정.기준_비중): 직접 확인 3 (계산 재검산, 코드 직접 실행, 오류 여부·출력 형식)
                            근거 대조 2 (질문 조건·지문·출처·위키백과·논문 DB와 비교하는 기준)
                            간접 비교 1 (③ 상위 모델 답변 일치도, ④ 답변 내부 일관성)
     설정.합치는_방법 = "가장 높은 값" 으로 바꾸면 예전 방식(기준 중 가장 높은 위험도)으로 계산해요.
  3) 프로그램이 직접 확인한 결정적 기준이 위험도 1이면 종합 위험도를 최소 0.8로 올려요.
     실행·계산으로 틀린 것이 확실한데 평균에 묻히지 않게 하려는 거예요.
  4) (예전 방식에서만) 기준 2개 이상이 함께 0.3 이상이면 최소 0.6으로 올려요.
  5) 등급: 0.05 미만 '문제 없음', 0.05 이상 0.25 미만 '보통', 0.25 이상 '위험'
     (예선에서 각 등급의 실제 환각 비율 3.5% / 12.3% / 54.8%, 전체 평균 5.8%)
  6) 환각 종류별(사실 상충·입력 상충·맥락 상충)로 가장 높은 위험도도 따로 보여 줘요.
  7) AI 없이 검사하면 '간이 검사'라고 표시해요. 사실 지식형·출처 인용형은 AI·웹 기준이 있어야 제대로 확인돼요.
